# Статистика прохождений

Игра пишет по одной записи на попытку прохождения этапа. Записи уходят прямо
в базу Supabase — своего сервера у нас нет и не нужно.

Пока в `src/config.js` не прописаны адрес и ключ, сбор выключен: игра работает
ровно так же, просто молча.

## Что делать в Supabase

Один раз, руками, потому что для этого нужен ваш аккаунт.

**1. Завести проект** на supabase.com. Регион — ближе к игрокам.

**2. Создать таблицу.** SQL Editor → New query → вставить и выполнить:

```sql
create table if not exists runs (
  id           bigint generated always as identity primary key,
  created_at   timestamptz not null default now(),
  player       text not null,   -- случайный номер, живёт в браузере игрока
  build        text,            -- версия игры плюс номер коммита
  route        int,
  stage        int,
  hero_level   int,
  lives_max    int,
  abilities    text[],          -- что куплено в магазине
  outcome      text,            -- finish | lives | time | quit
  ms           int,             -- сколько заняла попытка
  deaths       int,
  coins_taken  int,
  coins_total  int,
  coins_missed int[],           -- номера несобранных монет
  stars        int,
  events       jsonb            -- [{t, x, y, by}] — каждая смерть
);

create index on runs (route, stage);
create index on runs (created_at);
```

**3. Закрыть чтение и разрешить только запись.** Там же:

```sql
alter table runs enable row level security;

-- Игра умеет только добавлять записи. Читать чужие данные ей нельзя, поэтому
-- политики на чтение нет вовсе: смотреть статистику будете из панели.
create policy "игра только пишет"
  on runs for insert to anon
  with check (
    ms between 0 and 3600000
    and deaths between 0 and 500
    and coins_taken between 0 and 1000
    and stars between 0 and 3
    and length(player) between 8 and 64
  );
```

Проверки в `with check` — не формальность. Ключ лежит в браузере у каждого
игрока, то есть виден всем, и заведомую чушь в базу класть не должно быть
можно. От целенаправленной порчи это не спасёт, но от случайной и от скучающего
шутника — вполне.

**4. Взять адрес и ключ.** Settings → API: `Project URL` и ключ `anon public`.

**5. Прислать их мне** — пропишу в `src/config.js` и выложу.

## Что собирается

Одна строка на попытку. Ничего, что относится к человеку: ни имени, ни почты,
ни адреса. Номер игрока — случайное число из его же браузера, нужно ровно для
того, чтобы отличить десять попыток одного человека от одной попытки десяти
разных.

Смерти пишутся подробно: время, координаты и от чего. Причины: `pit` (упал),
`boulder`, `dropSpike`, `spike`, `fire`, `quill`, `tongue` и буква монстра —
`m`, `f`, `l`, `e`, `b`, `d`, `w`, `j`, `z`.

Несобранные монеты хранятся номерами, а не координатами: карта у всех
одинаковая, поэтому номера достаточно.

## Как читать

**Сколько занимает прохождение и сколько раз умирают**

```sql
select route, stage,
       count(*)                                    as попыток,
       round(avg(ms) filter (where outcome = 'finish') / 1000.0) as сек_на_проход,
       round(avg(deaths), 2)                       as смертей_в_среднем,
       round(100.0 * count(*) filter (where outcome = 'finish') / count(*)) as процент_прошли
from runs
group by route, stage
order by route, stage;
```

**Где умирают чаще всего** — по клеткам карты:

```sql
select stage,
       (e ->> 'by')                as от_чего,
       (e ->> 'x')::int / 60       as клетка,
       count(*)                    as смертей
from runs, jsonb_array_elements(events) e
where route = 1
group by stage, от_чего, клетка
having count(*) > 3
order by смертей desc
limit 30;
```

**Какие монеты не берут** — кандидаты в недостижимые:

```sql
select stage, монета, count(*) as не_взяли, count(*) filter (where true) as из_попыток
from runs, unnest(coins_missed) as монета
where route = 1
group by stage, монета
order by не_взяли desc
limit 30;
```

Монета, которую не взял почти никто за сотню попыток, скорее всего недостижима
— это ошибка карты, а не привычка игроков. Сравнивать надо с общим числом
попыток на этом этапе.

**Кто убивает чаще**

```sql
select (e ->> 'by') as от_чего, count(*) as смертей
from runs, jsonb_array_elements(events) e
group by от_чего
order by смертей desc;
```

## Оговорки

**Проект засыпает.** На бесплатном тарифе Supabase останавливает базу после
недели без запросов, будится вручную из панели.

**Часть данных не дойдёт.** Блокировщики режут запросы к чужим доменам —
процентов пять-десять записей потеряется. На выводы это не влияет, но помнить
стоит: доли считать можно, абсолютные числа занижены.

**Записи копятся при обрыве связи.** Что не ушло — лежит в браузере игрока и
уходит при следующем запуске, но не больше двадцати последних.
